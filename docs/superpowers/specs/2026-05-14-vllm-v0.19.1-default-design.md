# Design: Update Default vLLM Version to v0.19.1

**Date:** 2026-05-14
**Status:** Approved
**Author:** Claude Code

## Problem Statement

The blis-campaign currently uses vLLM v0.15.1 as the default version for stock (non-observability) deployments. We need to update to v0.19.1 to use a newer vLLM version for experiments that don't require observability features.

## Solution

Update the Docker image field in both stock values files from `vllm/vllm-openai:v0.15.1` to `vllm/vllm-openai:v0.19.1`. This affects experiments where `observability: false` or the field is absent.

## Design

### Implementation Details

**Files Modified:**
1. `tektoncsample/blis-orc/values.yaml` - Line 57
2. `tektoncsample/blis-inference-perf/values.yaml` - Line 57

**Change:**
```yaml
# Before
containers:
- name: "vllm"
  image: "vllm/vllm-openai:v0.15.1"

# After
containers:
- name: "vllm"
  image: "vllm/vllm-openai:v0.19.1"
```

### Behavior

**Stock Deployments (observability: false or absent):**
- ORC harness: Uses `vllm/vllm-openai:v0.19.1`
- inference-perf harness: Uses `vllm/vllm-openai:v0.19.1`

**Observability Deployments (observability: true):**
- ORC harness: Continues using `ghcr.io/inference-sim/vllm:0.6.8` (no change)
- inference-perf harness: Continues using `ghcr.io/inference-sim/vllm:0.6.8` (no change)

**Selection Logic (in generate.py:465-474):**
```python
use_observability = exp.get("observability", False)

if harness == "orc":
    base_values = (base_values_orc_observability if use_observability
                  else base_values_orc_stock)  # <- Will get v0.19.1
else:
    base_values = (base_values_inference_perf_observability if use_observability
                  else base_values_inference_perf_stock)  # <- Will get v0.19.1
```

### Backward Compatibility

- All existing experiments in `experiments.json` without an `observability` field will automatically use v0.19.1 on next generation
- Experiments with `observability: true` continue using the custom observability image
- No changes required to `experiments.json` or `generate.py`

### Files NOT Modified

- `tektoncsample/blis-orc/values-observability.yaml` - Uses `ghcr.io/inference-sim/vllm:0.6.8`
- `tektoncsample/blis-inference-perf/values-observability.yaml` - Uses `ghcr.io/inference-sim/vllm:0.6.8`
- `blis-campaign/generate.py` - Selection logic unchanged
- `blis-campaign/experiments.json` - No experiment modifications needed

## Rationale

### Why v0.19.1?

- Newer vLLM version with improvements and bug fixes
- Stock Docker Hub image available (`vllm/vllm-openai:v0.19.1`)
- Maintains separation between stock and observability deployments

### Why Direct Image Update?

- **Simplest approach:** Two line changes, no logic modifications
- **Follows existing pattern:** Observability templates already use different images
- **No additional complexity:** No new configuration dimensions or version fields
- **Clear separation:** Stock vs. observability continue to be distinct configurations

### Why Not Add Version Field to Experiments?

- YAGNI: No current requirement for per-experiment version flexibility
- Would add complexity to `generate.py` for no immediate benefit
- Version changes are rare enough that updating values files directly is acceptable

## Testing Strategy

1. **Validation:**
   - Run `python blis-campaign/generate.py --experiments experiments.json --output test-campaign/`
   - Verify generated values files contain `vllm/vllm-openai:v0.19.1` for non-observability experiments
   - Verify observability experiments still use `ghcr.io/inference-sim/vllm:0.6.8`

2. **Deployment Testing:**
   - Deploy a stock experiment to cluster
   - Verify vLLM pod uses v0.19.1 image
   - Run basic inference test to confirm functionality

3. **Backward Compatibility:**
   - Regenerate existing experiments
   - Verify no breaking changes to pipeline YAML structure
